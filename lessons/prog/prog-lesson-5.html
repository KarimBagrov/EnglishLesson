Зачем нужна типизация, как описывать объекты и что такое дженерики

JUNIOR · 2026 · ≈ 90 МИН

1 Введение: зачем нужен TypeScript

Представь, что ты собираешь шкаф из IKEA. В обычном JavaScript тебе дают кучу деталей без инструкции и говорят: «Собери как-нибудь». Ты можешь прикрутить полку к потолку, и никто тебя не остановит, пока шкаф не развалится (ошибка в рантайме).

TypeScript — это инструкция с чертежом. Ты заранее описываешь, что «эта деталь — это дверца, она крепится сюда». Если ты попытаешься прикрутить дверцу к полу, редактор кода (VS Code) сразу подчеркнет это красным и скажет: «Ошибка!». Ты исправляешь ошибку до того, как код попадет к пользователю.

💡 Главная мысль: TypeScript — это JavaScript с типами. Весь код компилируется обратно в обычный JS, чтобы его понимал браузер. Но процесс разработки становится в разы безопаснее и удобнее.

2 Базовые типы

В TypeScript мы указываем тип после двоеточия. Синтаксис простой: let имя: тип = значение;.

2.1. Примитивы

let name: string = "Иван";
let age: number = 25;
let isStudent: boolean = true;

Если ты попытаешься записать в age строку, TS выдаст ошибку еще в редакторе.

2.2. Массивы

let numbers: number[] = [1, 2, 3];
let names: string[] = ["Анна", "Иван"];
// Альтернативная запись: Array<number>

2.3. any vs unknown

any — это «отключить типизацию». Переменная с any может принимать что угодно. Это плохо, потому что мы теряем все преимущества TS.

let data: any = "строка";
data = 123; // Ошибки нет, но и подсказок нет

unknown — это безопасная альтернатива. Переменная с unknown тоже может принимать что угодно, но перед использованием её нужно проверить (сделать typeof). Это заставляет думать.

3 Интерфейсы и типы

Когда у тебя есть объект с множеством свойств, писать { name: string; age: number; city: string } каждый раз долго. Для этого есть интерфейсы (или псевдонимы типов).

3.1. Интерфейс

interface User {
name: string;
age: number;
city?: string; // ? означает, что свойство необязательное
}
const user: User = { name: "Иван", age: 25 };

Теперь если ты забудешь передать name или передашь age как строку, TS сразу это подсветит.

3.2. Тип (type)

type работает почти так же, но может описывать не только объекты, но и объединения (union).

type Status = "success" | "error" | "loading";
let currentStatus: Status = "success"; // Только эти три строки разрешены

4 Дженерики (Generics)

Представь, что у тебя есть коробка. Ты можешь положить туда яблоко, а можешь — книгу. Но если ты положил яблоко, было бы странно достать оттуда книгу. Дженерики позволяют сказать: «Это коробка для яблок» или «Это коробка для книг».

Они обозначаются угловыми скобками <T> (T — от слова Type).

4.1. Пример без дженериков

function identity(value: any): any {
return value;
}
// Мы теряем информацию о типе

4.2. С дженериками

function identity<T>(value: T): T {
return value;
}
const num = identity(5); // TS знает, что num — это number
const str = identity("Привет"); // TS знает, что str — это string

Дженерики часто используются в массивах (Array<T>), промисах (Promise<T>) и функциях работы с API.

5 Как спросят на собеседовании

Вопрос: Чем any отличается от unknown?

Ответ: «any отключает проверку типов полностью, с ним можно делать что угодно. unknown — это безопасный тип, который может содержать что угодно, но перед использованием его нужно проверить (сделать typeof или приведение). unknown лучше, потому что заставляет разработчика явно обрабатывать возможные типы.»

Вопрос: Что такое дженерики?

Ответ: «Это способ создавать компоненты или функции, которые работают с разными типами, но при этом сохраняют информацию о конкретном типе. Например, функция identity<T>(value: T): T возвращает то же, что и приняла, и TS знает, какой именно тип был возвращен.»

6 Типичные ошибки

Ошибка 1: Использовать any везде

❌ const data: any = fetchData();
Мы не знаем, что внутри data, и теряем подсказки.
✅ interface Data { id: number; name: string; }
Теперь TS подскажет, какие поля есть.

Ошибка 2: Забыть про ?

❌ interface User { name: string; age: number; }
Если age необязателен, TS будет ругаться.
✅ interface User { name: string; age?: number; }

7 Мини-задания

Задание 1

Опишите интерфейс для объекта product с полями: id (число), name (строка), price (число), description (необязательная строка).

Показать ответ
interface Product {
id: number;
name: string;
price: number;
description?: string;
}
Задание 2

Какой тип будет у переменной x?

function getFirst<T>(arr: T[]): T {
return arr[0];
}
const x = getFirst([1, 2, 3]);
Показать ответnumber. TS выводит тип из массива [1, 2, 3] — это массив чисел, значит T = number.
