Урок 2 · Область видимости и Замыкания

Почему переменные видны не везде, что такое поднятие и как работает классическая задача с setTimeout

1 Введение: где живут переменные

Представь, что у тебя есть дом (твоя программа) и в нём есть комнаты (функции и блоки кода). Переменные — это вещи. Если ты положил молоток в гостиной (в глобальной области), ты можешь взять его из любой другой комнаты. Но если ты положил его в закрытый ящик в спальне (в локальную область), из кухни ты его уже не достанешь.

Область видимости (Scope) — это правила, которые определяют, из какого места программы ты можешь «увидеть» переменную, а из какого — нет.

💡 Главная мысль: В JavaScript есть глобальная область видимости (видна везде), функциональная (видна внутри функции) и блочная (видна внутри фигурных скобок {}). Понимание этой разницы — половина успеха на собеседовании.

2 var vs let vs const

До 2015 года в JavaScript был только var. Потом вышла новая версия (ES6), и появились let и const. Они исправили старые проблемы.

2.1. var — старый и опасный (функциональная область)

var виден во всей функции, даже если объявлен внутри if или цикла. Это называется функциональной областью видимости.

function testVar() {
if (true) {
var x = 10;
}
console.log(x); // 10! Хотя x объявлен внутри if
}

В маленькой функции это не проблема. Но в большой — можно случайно изменить переменную, которая не должна была меняться.

2.2. let — умный (блочная область)

let виден только внутри блока {}, где он объявлен. Вышел за скобки — переменная недоступна.

function testLet() {
if (true) {
let x = 10;
}
console.log(x); // Ошибка! x is not defined
}

2.3. const — строгий (блочная область + запрет изменения)

const работает как let, но не позволяет перезаписать значение.

const a = 5;
a = 10; // Ошибка! Assignment to constant variable.

Важно: Если const хранит объект или массив, ты можешь менять его внутренности (например, добавлять элементы в массив), но не можешь перезаписать саму переменную.

3 Поднятие (Hoisting)

Представь, что JavaScript перед выполнением кода проходит по нему сверху вниз и «поднимает» все объявления переменных и функций на самый верх. Это называется hoisting.

Из-за этого код может работать до того, как ты объявил переменную.

3.1. С var

console.log(x); // undefined (не ошибка!)
var x = 5;

JavaScript видит var x и как бы переносит его наверх: var x; (но без значения). Поэтому x существует, но равно undefined.

3.2. С let и const

console.log(x); // Ошибка! Cannot access 'x' before initialization
let x = 5;

let и const тоже поднимаются, но они попадают в временную мёртвую зону (TDZ). Это значит, что до строки с объявлением они существуют, но обращаться к ним нельзя — будет ошибка.

4 Цикл и setTimeout (классика собеседований)

Это, наверное, самый частый вопрос на собеседованиях. Давай разберем его по шагам.

4.1. Задача с var

Что выведет этот код?

for (var i = 0; i < 3; i++) {
setTimeout(() => console.log(i), 100);
}

Ответ: 3, 3, 3. Почему? Потому что var — это одна переменная на весь цикл. К моменту, когда setTimeout сработает (через 100 мс), цикл уже давно закончится, и i будет равно 3. Все три функции смотрят на одну и ту же переменную.

4.2. Задача с let

for (let i = 0; i < 3; i++) {
setTimeout(() => console.log(i), 100);
}

Ответ: 0, 1, 2. Почему? Потому что let создаёт новую переменную на каждой итерации цикла. Каждая стрелочная функция «запоминает» свою собственную i (замыкание).

5 Замыкания (Closures)

Замыкание — это когда функция «запоминает» переменные из той области видимости, где она была создана, даже если эта область уже завершила работу.

Представь, что ты собрал рюкзак с инструментами в комнате. Ты вышел из комнаты, но рюкзак остался с тобой. Ты можешь достать инструменты где угодно, потому что они «замкнуты» в твоем рюкзаке.

5.1. Пример

function createCounter() {
let count = 0; // это "рюкзак"
return function() {
count++;
return count;
};
}
const counter = createCounter();
console.log(counter()); // 1
console.log(counter()); // 2

Функция createCounter завершилась, но внутренняя функция всё ещё имеет доступ к count. Это и есть замыкание.

6 Как спросят на собеседовании

Вопрос: В чём разница между var, let и const?

Ответ: «var имеет функциональную область видимости и поднимается со значением undefined. let и const имеют блочную область видимости. const нельзя переприсвоить, но внутренности объекта менять можно.»

Вопрос: Что такое замыкание?

Ответ: «Замыкание — это способность функции запоминать переменные из внешней области видимости, даже после того, как эта область завершила выполнение. Пример: функция-счётчик, которая помнит своё значение между вызовами.»

7 Типичные ошибки

Ошибка 1: Использование var в цикле с асинхронностью

❌ for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i), 100); }
Выведет 3, 3, 3.
✅ for (let i = 0; i < 3; i++) { setTimeout(() => console.log(i), 100); }
Выведет 0, 1, 2.

Ошибка 2: Попытка изменить const

❌ const x = 5; x = 10;
✅ let x = 5; x = 10;
