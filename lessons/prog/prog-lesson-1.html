1 Введение: с чем едим JavaScript

Представь, что ты пришёл на кухню, чтобы приготовить борщ. У тебя есть кастрюля, нож, доска и продукты. Но если ты не знаешь, что кладут в борщ (свёклу, а не бананы) и в каком порядке (сначала бульон, потом зажарку), у тебя получится непонятная жижа.

JavaScript — это та же кухня. У нас есть «ингредиенты» (данные) и «действия» (операции). И есть строгие правила, как с ними обращаться. Если ты не знаешь правил — программа работает не так, как ты ожидаешь. А на собеседовании именно эти правила и проверяют.

💡 Главная мысль урока: JavaScript — это язык с динамической типизацией. Это значит, что мы не говорим заранее: «эта коробка только для чисел». Мы кладём в переменную что угодно, и JS сам решает, как с этим обращаться. Это даёт гибкость, но создаёт ловушки. Мы научимся их обходить.

1.1. Зачем вообще нужны переменные?

Переменная — это коробка с наклейкой. Наклейка — это имя. Внутри лежит значение. Например:

let age = 25; // в коробку с наклейкой "age" положили число 25
let name = "Иван"; // в коробку "name" положили текст

В отличие от строгих языков (например, C++ или Java), в JavaScript мы не обязаны указывать, что лежит в коробке. Мы можем положить туда число, потом достать и положить строку. Это и есть динамическая типизация.

2 Типы данных (разбираем с нуля)

В JavaScript всего 8 типов данных. Семь из них — «простые» (примитивы), и один — «сложный» (объект). Давай разберём каждый, как будто мы видим их впервые.

2.1. Примитивы — это «кирпичики»

Примитив — это простое значение, которое нельзя разбить на части. Как атом. Их семь:

ТипЧто этоПримерАналогия из жизни
string (строка)Текст в кавычках"Привет", 'JS'Записка на бумаге
number (число)Любое число (целое или дробное)42, 3.14, -10Цифра на калькуляторе
boolean (логическое)Только true (истина) или false (ложь)true, falseВыключатель: вкл/выкл
nullНамеренное отсутствие значенияnullПустая коробка, на которой написано «пусто»

symbolУникальный идентификатор (редко используется)Symbol("id")Уникальный штрих-код
bigintОчень большие целые числа12345678901234567890nДлинный номер счёта в банке

2.2. Объект — это «конструктор»

Всё, что не примитив — это объект. Объект может содержать в себе другие значения (в том числе другие объекты).

let user = { name: "Иван", age: 25 }; // обычный объект
let colors = ["красный", "синий"]; // массив — это тоже объект
function greet() { return "Привет"; } // функция — тоже объект

Представь, что примитив — это одна деталь Lego, а объект — это собранная из них фигурка. Она состоит из деталей, но сама является цельной вещью.

💡 Запомните навсегда: Оператор typeof показывает тип значения. Но есть историческая странность: typeof null возвращает "object". Это баг, который был в первых версиях JS. Его не исправили, потому что если исправить — сломаются миллионы старых сайтов. На собеседовании это спрашивают, чтобы проверить, знаете ли вы историю языка.

3 == vs === (главный вопрос собеседования)

В JavaScript есть два оператора сравнения: == (два знака равно) и === (три знака равно). Начинающие часто думают, что это одно и то же. Это не так.

3.1. Строгое сравнение === (как строгий учитель)

Оператор === сравнивает и значение, и тип. Если типы разные — он даже не смотрит на значения, сразу говорит false.

console.log(5 === 5); // true (число и число, значения равны)
console.log(5 === "5"); // false (число и строка — разные типы)
console.log(true === 1); // false (boolean и число)

Это как охранник в клубе: если у тебя нет нужного типа билета (например, ты пришёл с бумажкой вместо пластиковой карты), он тебя не пустит, даже если на бумажке написано «VIP».

3.2. Нестрогое сравнение == (как ленивый охранник)

Оператор == сначала приводит типы к одному, а потом сравнивает. Это называется приведением типов (type coercion).

console.log(5 == "5"); // true! (строка "5" превращается в число 5)
console.log(0 == false); // true! (false превращается в 0)
console.log("" == 0); // true! (пустая строка превращается в 0)

Этот охранник видит, что у тебя бумажка, говорит: «Ладно, я её заламинирую, будет похоже на карту», — и пропускает. Вроде удобно, но может пропустить кого угодно.

💡 Правило на всю жизнь: Всегда используйте ===. Единственное исключение — проверка на null == undefined (об этом ниже).

3.3. Почему == опасен на практике

Представь, что пользователь ввёл в поле «возраст» строку "0". Ты проверяешь: «если возраст равен 0, то показать ошибку». Пишешь if (age == 0). Но что если возраст — пустая строка ""? "" == 0 тоже true! И ты покажешь ошибку, хотя пользователь ничего не ввёл, а не ввёл ноль.

А если написать if (age === 0), то сработает только если это реально число 0. Строка "" или "0" не пройдут.

4 null vs undefined (две пустоты)

Оба этих значения означают «пусто». Но они означают разную пустоту. Это как два разных способа сказать «ничего».

4.1. undefined — «я не знаю, что тут»

undefined — это когда JavaScript сам ставит это значение, потому что переменная ещё не заполнена.

  • Ты объявил переменную, но не дал ей значение: let x; → x равно undefined.
  • Ты вызвал функцию, которая ничего не возвращает: function f() {} → f() равно undefined.
  • Ты обратился к свойству, которого нет: {}.name → undefined.

Это как пустая коробка, на которой написано: «Содержимое не задано».

4.2. null — «я специально положил пустоту»

null — это когда ты сам (разработчик) говоришь: «Здесь пусто, и это правильно». Это осознанное решение.

let currentUser = null; // пользователь ещё не вошёл
// ... позже, когда вошёл:
currentUser = { name: "Иван" };

Это как пустая коробка, на которой ты маркером написал: «Пусто. Это нормально».

4.3. Главное сравнение

ОперацияРезультатПочему
null == undefinedtrueПри нестрогом сравнении они считаются равными (оба — «пустота»)
null === undefinedfalseРазные типы, строгое сравнение их не пропускает
typeof null"object"Исторический баг языка
typeof undefined"undefined"Всё логично
💡 Лайфхак: Вместо if (x === null || x === undefined) можно написать if (x == null). Это единственный случай, когда == официально полезен.

5 Как JS приводит типы (магия под капотом)

JavaScript — язык, который очень старается сделать хоть что-то, вместо того чтобы выдать ошибку. Когда ты складываешь число и строку, он не говорит: «Так нельзя». Он приводит одно к другому. Это и есть type coercion.

5.1. Оператор + (двойная жизнь)

У плюса две роли: сложение чисел и склеивание строк (конкатенация). Какую роль он выберет?

Правило: Если хотя бы один операнд (то, что стоит слева или справа) — строка, то плюс работает как клей.

console.log(5 + 5); // 10 (оба числа — сложение)
console.log(5 + "5"); // "55" (строка справа — склеивание)
console.log("5" + 5); // "55" (строка слева — склеивание)
console.log("5" + "5"); // "55" (обе строки — склеивание)

Это как если бы у тебя был клей и молоток в одном инструменте. Если видишь бумагу (строку) — клеишь. Если видишь гвоздь (число) — стучишь.

5.2. Операторы -, *, / (всегда математика)

Минус, умножить и делить всегда превращают всё в числа. Если строка похожа на число — она станет числом. Если не похожа — получится NaN (Not a Number).

console.log(5 - "5"); // 0 (строка превратилась в 5)
console.log("10" * 2); // 20
console.log("привет" - 1); // NaN (нельзя превратить в число)

5.3. Boolean в математике

true превращается в 1, false — в 0.

console.log(true + 1); // 2
console.log(false + 1); // 1

6 Truthy и Falsy (кто прав, кто виноват)

В условиях (if, while) JavaScript не требует, чтобы ты передавал именно true или false. Он принимает любое значение и сам решает, «правда это или ложь».

Все значения делятся на две группы: falsy (ведут себя как ложь) и truthy (ведут себя как правда).

6.1. Falsy — всего 6 штук (и их надо знать наизусть)

false
0
-0 (минус ноль, редкость)
"" (пустая строка)
null
undefined
NaN (Not a Number)

Всё остальное — truthy. Даже пустой массив [], даже пустой объект {}, даже строка с пробелом " ".

6.2. Ловушка со строкой "0"

console.log(Boolean(0)); // false (число ноль)
console.log(Boolean("0")); // true! (строка с нулём — это не пусто)

Это очень частая ошибка. Строка "0" — это текст, в ней есть символ. А 0 — это число. Разные вещи.

7 Как спросят на собеседовании (готовые ответы)

Ниже — вопросы, которые задают 90% интервьюеров на junior-позиции. Выучи формулировки, но не заучивай — пойми.

Вопрос 1: В чём разница между == и ===?

Ответ: «== сравнивает с приведением типов, === — без приведения. Если типы разные, === сразу даёт false. В современном коде всегда используют ===, кроме проверки на null == undefined, которая даёт true и позволяет проверить оба случая одной проверкой.»

Вопрос 2: Чем null отличается от undefined?

Ответ: «undefined — это когда значение не задано системой: переменная объявлена без инициализации, функция ничего не вернула, свойство не существует. null — это намеренное отсутствие значения, которое ставит разработчик. При этом typeof null возвращает "object" — это исторический баг JavaScript.»

Вопрос 3: Что выведет 5 + "5"?

Ответ: «Выведет строку "55". Оператор + при наличии строки выполняет конкатенацию, поэтому число 5 приводится к строке. Если бы было 5 - "5", результат был бы 0, потому что - всегда приводит к числу.»

Вопрос 4: Назовите falsy-значения

Ответ: «В JavaScript 6 falsy-значений: false, 0, -0, "", null, undefined, NaN. Всё остальное — truthy. Важно помнить, что строка "0" — truthy, потому что это непустая строка, а пустой массив [] и объект {} тоже truthy.»

8 Типичные ошибки (и как их избежать)

Ошибка 1: Использование == вместо ===

❌ if (x == 0) { ... }
Если x = "" или x = false, условие тоже сработает — неожиданно.
✅ if (x === 0) { ... }
💡 Почему именно так?

== приводит "" к 0, поэтому "" == 0 даёт true. С === такого не будет: типы разные, сразу false.

Ошибка 2: Путать null и undefined

❌ let user; // undefined, но разработчик думает, что это null
✅ let user = null; // явно говорим: пользователя нет
💡 Почему именно так?

undefined — это «значение не задано». Если вы хотите сказать «здесь пусто намеренно», используйте null. Это делает код понятнее для коллег.

Ошибка 3: Ожидать число от 5 + "5"

❌ console.log(5 + "5"); // ожидание 10
✅ console.log(5 + Number("5")); // 10
💡 Почему именно так?

Если один операнд — строка, + делает конкатенацию. Чтобы сложить числа, нужно явно привести строку к числу через Number(), parseInt() или + перед переменной.

9 Мини-задания (проверь себя)

Задание 1

Что выведет этот код и почему?

console.log(1 + "2" + 3);
Показать ответ"123". Сначала 1 + "2" → "12" (конкатенация). Потом "12" + 3 → "123" (снова конкатенация).
Задание 2

Что выведет этот код?

console.log(null == undefined);
console.log(null === undefined);
Показать ответtrue и false. При == они считаются равными (оба означают пустоту). При === — разные типы, поэтому false.
Задание 3

Какие из этих значений falsy?

0, "0", "", [], null, undefined, NaN, false
Показать ответFalsy: 0, "", null, undefined, NaN, false. Truthy: "0" (непустая строка), [] (пустой массив — объект).
Задание 4

Что выведет?

console.log(typeof null);
Показать ответ"object". Это исторический баг JavaScript: null должен был быть отдельным типом, но из-за ошибки в первых версиях движка он определяется как объект. Баг не исправили, чтобы не ломать старый код.
